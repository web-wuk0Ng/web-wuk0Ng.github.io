类型注解@type

@type是fastjson中的一个特殊注解，用于标识JSON字符串中的某个属性是一个Java对象的类型。具体来说，当fastjson从JSON字符串反序列化为Java对象时，如果JSON字符串中包含@type属性，fastjson会根据该属性的值来确定反序列化后的Java对象的类型，比如这个demo（需要注意的是：由于fastjson在1.2.24之后默认禁用AutoType，因此这里我们通过ParserConfig.getGlobalInstance().addAccept("java.lang");来开启，否则会报错autoType is not support）：

我们发现此时生成的json自带@type字段了，其实就是在调用toJSONString方法的时候，参数里面多了一个SerializerFeature.WriteClassName方法。传入SerializerFeature.WriteClassName可以使得Fastjson支持自省，开启自省后序列化成JSON的数据就会多一个@type，这个是代表对象类型的JSON文本

FastJson的漏洞就是这个@type功能去产生的，在对该JSON数据进行反序列化的时候，会去调用指定类中对于的get/set/is方法，我们接下来详细分析

3.漏洞攻击完整链路

前提条件：

1.服务器开启AutoType

2.攻击者可以完全控制传入的json字符串

攻击流程：

  1. 攻击者构造恶意 JSON：{"@type":"危险类全类名",其他字段...}
  2. 把这个恶意 JSON 发给后端接口
  3. 后端调用 JSON.parseObject(json, Object.class)
  4. Fastjson 解析 JSON，读取@type，拿到攻击者指定的危险类名
  5. 反射加载这个危险类，调用无参构造器创建实例
  6. 继续解析 JSON 里其他字段，自动调用对应 setter 方法赋值
  7. 👉 关键：这个危险类的 setter/getter 内部，藏有恶意逻辑（gadget）
  8. 执行到 getter/setter 时，触发代码，最终走到Runtime.exec()实现命令执行

不是 @type 直接执行命令 @type 只负责：告诉 Fastjson，实例哪一个类。 真正恶意代码，藏在这个类属性的 get/set 方法里面

而我们分析这个payload就知道这里实际上就是我们学过的TemplatesImlp动态加载字节码

即构造一个TemplatesImpl类的反序列化字符串，其中_bytecodes是我们构造的恶意类的类字节码，这个类的父类是AbstractTranslet，最终这个类会被加载并使用newInstance()实例化。在反序列化过程中，由于getter方法getOutputProperties()满足条件，将会被fastjson调用，而漏洞利用的限制条件也很明显：需要代码中加了Feature.SupportNonPublicField，即允许向对象的非public属性赋值

链路分析-TesmplatesImpl动态加载字节码

Fastjson 在解析 JSON 时，识别@type指定TemplatesImpl类，反序列化填充它的私有字段；当访问_outputProperties字段，会触发getOutputProperties()，内部加载_bytecodes里自定义字节码；因为恶意类继承AbstractTranslet，JVM 加载该类的瞬间执行static静态代码块，执行系统命令

1.EXP 准备阶段（FastJsonTemplatesDemo.main）

  • javassist 读取已经编译好的 RCETest.class 字节码，做 Base64 编码
  • 构造 JSON payload：

字段说明：

  • @type：fastjson1.2.24 默认开启 AutoType，指定要反序列化的目标类TemplatesImpl
  • _bytecodes：TemplatesImpl 内置属性，存放要加载的字节码数组（RCETest）
  • _name：类名，随便填，用来做类加载标识
  • _tfactory：Transformer 工厂，填空对象即可
  • _outputProperties：触发入口！ 只要给这个字段赋值，会调用 getter getOutputProperties()

2.Fastjson 反序列化入口

Feature.SupportNonPublicField 是必须项： TemplatesImpl 的_bytecodes/_name/_tfactory/_outputProperties全部是private私有成员；不加这个 Feature，fastjson 无法给私有字段赋值，漏洞无法触发。

fastjson 解析 JSON，看到@type，反射实例化 TemplatesImpl 对象，依次填充各个私有字段

3.关键触发：填充 _outputProperties → 自动调用 getOutputProperties()

fastjson 在给_outputProperties赋值时，会调用该字段的 getter 方法 TemplatesImpl.getOutputProperties()

getOutputProperties() 内部执行 newTransformer()

4.newTransformer () → defineTransletClasses () 加载_bytecodes 字节码

defineTransletClasses 会：

  1. 读取 _bytecodes 数组里面的字节码
  2. 自定义 ClassLoader，把字节码动态定义成 Java 类
  3. 强制校验：这个类必须继承 AbstractTranslet（这就是 RCETest 要继承这个抽象类的原因）
  4. 校验通过后，JVM 加载这个 RCETest 类

5.JVM 加载 RCETest 类 → 执行 static 静态代码块（命令执行）

执行系统命令，Mac 弹出计算器
